# VoxDelta Local PoC UI

한 화면에서 음성 파일 업로드 또는 마이크 녹음, 파이프라인 진행 확인, 화자 역할 확인, calibrated XLS-R 감정 결과 확인까지 이어지는 로컬 PoC입니다.

## 실행

Node.js 24와 backend의 Python/uv 환경이 준비된 상태에서:

```bash
cd frontend
npm install
npm run poc
```

브라우저에서 `http://127.0.0.1:5173`을 엽니다. `npm run poc`은 `backend/.env.poc`이 있으면 그 파일을, 없으면 `backend/.env`를 읽고, 실행할 때마다 임시 capability token을 생성해 FastAPI와 Vite proxy에 함께 전달합니다. 토큰은 파일이나 브라우저 저장소에 기록하지 않습니다. provider API 키는 백엔드 프로세스에만 전달되고 개발 서버에는 넘기지 않습니다.

이미 5173에서 다른 PoC가 돌고 있다면 `VOXDELTA_POC_PORT`로 포트를 옮깁니다. Vite와 Playwright가 같은 값을 씁니다.

```bash
VOXDELTA_POC_PORT=5199 npm run poc
```

provider 선택은 백엔드 설정을 그대로 따릅니다. 화자 분리 기본값은 로컬 `nemotron-3-local`이며 첫 실행 전에 [`docs/nemotron-3-local-setup.md`](../docs/nemotron-3-local-setup.md)의 런타임·모델 설치가 필요합니다. `VOXDELTA_DIARIZATION_PROVIDER=pyannoteai-precision`으로 명시하면 화자 분리 단계만 원격이 되고(동의 게이트가 나타남) 나머지는 로컬로 남습니다. 로컬 모델을 처음 받는 절차는 [`backend/README.md`](../backend/README.md)의 **Local model providers**에 있습니다.

같은 네트워크의 다른 기기에서 확인할 때는 UI만 모든 인터페이스에 바인딩합니다. 백엔드는 계속 loopback에 남습니다.

```bash
npm run poc -- --host 0.0.0.0
```

이 경우 Vite proxy를 통해 PoC API도 같은 네트워크에서 접근할 수 있으므로 신뢰할 수 있는 LAN에서만 실행합니다.

리버스 프록시(예: `tailscale serve`) 뒤에 두면 Vite는 자기가 모르는 Host 이름을 403으로 막습니다. 그 이름을
`backend/.env.poc`의 `VOXDELTA_POC_ALLOWED_HOSTS`에 쉼표로 구분해 하나씩 적어 주세요. 적힌 이름만 통과하고
나머지는 그대로 거절되므로 DNS rebinding 방어는 유지됩니다. 전부 허용하는 설정은 두지 않습니다.

```
VOXDELTA_POC_ALLOWED_HOSTS=my-host.tailnet-name.ts.net
```

## 화면이 지키는 약속

- **로컬 전용 문구는 확인 후에만 표시합니다.** 시작할 때 `GET /api/config/providers`를 읽어, 모든 단계의 provider가 로컬이고 전송 선언이 없을 때만 "외부로 전송되지 않습니다"라고 말합니다. 원격 provider가 하나라도 있으면 그 단계와 전송 대상을 이름으로 밝히고, 설정을 읽지 못하면 보증할 수 없다고 말합니다.
- **오디오가 밖으로 나가면, 나가기 전에 동의를 받습니다.** 원격 단계가 하나라도 있으면 업로드 버튼 위에 전송 고지가 뜹니다. 어느 단계가 무엇을 어느 provider로 보내는지, 그 입력이 최대 몇 시간까지 남는지(`retention_window_hours`), 보관 정책 원문이 어디인지를 백엔드가 준 값으로 그대로 적고, 체크박스를 켜기 전에는 `POST /api/jobs`를 호출하지 않습니다. 동의는 녹음 한 건에만 유효해서 "새 음성 분석"을 누르면 풀립니다. provider 설정을 아직 읽는 중이거나 읽지 못했을 때도 제출은 막힙니다. 로컬 전용이라고 확인되기 전에 오디오를 올릴 수는 없습니다.
- **원격 단계가 있어도 전사는 로컬에 남습니다.** pyannoteAI 요청은 `transcription`을 끄고 나가므로 전송 선언에 전사문이 없고, 화면은 그 사실을 disclosure에서 읽어 확인한 뒤에만 "전사문은 어느 단계에서도 전송되지 않습니다"라고 적습니다.
- **낮은 확신도와 abstention을 중립으로 표시하지 않습니다.** 백엔드가 `operational_state = uncertain`이거나 calibration이 abstain으로 판정한 구간은 확률 분포에서 중립이 1위여도 "판단 불확실"로만 표시하고, 분포를 결론으로 읽지 말라고 안내합니다. 보정 정보가 없는 결과는 원시 확신도라고 밝힙니다.
- **로컬에 남는 데이터를 정리합니다.** "새 음성 분석"과 "분석 중단하고 삭제"는 모두 `DELETE /api/jobs/{id}`를 호출해 오디오와 중간 결과를 지웁니다. 삭제가 실패하면 화면을 그대로 두고 그 사실을 알립니다.
- **시각 인코딩이 판단의 강도를 그대로 반영합니다.** 상태 색(`--state-*`)은 만족→안정→불만족→격앙 순서의 척도이며, 이 척도에 색을 얹는 마크에는 항상 텍스트 라벨이 함께 붙습니다. `판단 보류`는 다섯 번째 색이 **아니라** 속 빈 점선 마크로 그립니다. 색각 이상 정도와 무관하게 보류를 상태로 오독할 수 없어야 하기 때문입니다. 감정 분포는 강조(emphasis) 형식이라 1위 감정만 강조색을 갖고 나머지는 회색으로 물러나며, 보류된 결과는 **아무것도 강조하지 않습니다**. 감정 흐름 선은 보류 구간에서 끊어집니다. 이어 그리면 모델이 하지 않은 판단을 보간하게 됩니다.
- **Silver는 사람이 확인해야 정답이 됩니다.** 헤더의 "Silver 검수" 탭은 같은 앱의 다른 화면이며, 같은 로컬 백엔드를 같은 capability로 읽습니다. 초안 목록은 발화 수와 다이제스트만 받아 오므로 무엇을 열지 고르는 동안에는 어떤 말도 보이지 않습니다. 초안을 열면 검증에서 탈락한 발화 수와 그 규칙을 먼저 보여 주고, 화자·시작·종료·전사문·감정을 고칠 수 있습니다. 확정 버튼은 검수자 식별자와 "확인했다"는 체크가 모두 있고, 백엔드가 거절할 값이 하나도 없을 때만 실제로 요청을 보냅니다. 확정본은 한 번만 기록되며, Silver 초안은 이 과정에서 바뀌지 않습니다.
- **백엔드 계약을 그대로 따릅니다.** 역할 확인은 관찰된 화자가 정확히 두 명일 때만 제출할 수 있고, 그 외에는 제출 대신 이유를 설명합니다. 공개 오류 코드는 실행 가능한 한국어 안내로 옮깁니다.

## 확인

```bash
npm test          # Vitest: API 계약, 오류 안내, 전송 고지·동의 게이트, arc 기하, Silver 검수, 전체 여정
npm run build     # tsc --noEmit x2 + vite build
npm run test:e2e  # Playwright desktop/mobile, API 모킹 smoke
```

Playwright는 기본 포트를 쓰므로, 미리보기를 띄워 둔 채로 돌리려면 포트를 옮겨 주세요. 스크린샷은
`test-results/`에 남고 `VOXDELTA_SCREENSHOT_DIR`로 위치를 바꿀 수 있습니다.

```bash
VOXDELTA_POC_PORT=5199 npm run test:e2e
```

상태 색을 바꾸려면 `scripts/validate_palette.js`류의 대비/색각 검증을 다시 돌리고 `src/styles.css` 상단 주석의 수치를 갱신해 주세요.

Playwright smoke는 실제 모델을 호출하지 않고 API 응답을 고정해, 전송 고지 → 동의 → 업로드 → 역할 확인 → uncertain 결과 안내 → 로컬 삭제까지를 데스크톱과 모바일에서 확인합니다. 고정 응답은 화자 분리를 pyannoteAI Precision-2로 선언하므로 동의 게이트도 함께 지나갑니다.

## 알려진 PoC 한계

- 화면을 새로 고치면 진행 중인 job id를 잃습니다. 재접속용 저장소를 두지 않습니다.
- `POST /roles`와 `POST /retry`는 백엔드에서 남은 파이프라인을 동기로 실행하므로, 그동안 진행률이 멈춘 것처럼 보입니다. 화면이 이를 문구로 알립니다.
- 로컬 모델은 CPU에서 돕니다. 3분 남짓한 통화 한 건이 업로드부터 리포트까지 대략 통화 길이만큼 걸리고, 그 대부분은 화자 분리와 전사입니다. 업로드 직후 화면이 오래 멈춘 것처럼 보이는 것은 정상입니다.
- 화자 귀속의 품질은 그 녹음에서의 화자 분리 품질까지입니다. 짧게 주고받는 구간에서는 한 사람의 말이 상대의 발화로 묶여 들어갈 수 있고, 그러면 그 문장은 감정 분석 대상에서 빠지거나 반대로 잘못 포함됩니다. 역할 확인 화면은 화자 두 명과 오디오 미리듣기만 보여 주므로, 확인은 전사가 아니라 소리로 합니다.
- 업로드 크기와 오디오 길이 제한은 백엔드 설정값이며 공개 엔드포인트로 노출되지 않습니다. 화면은 숫자를 추측하지 않고 거절 사유만 안내합니다.
- 결과 내보내기, 이전 분석 목록, 다중 job 관리는 범위 밖입니다.
- 동의는 이 브라우저 세션의 화면 상태로만 남습니다. 감사 기록으로 남기지 않고 백엔드로도 보내지 않으므로, 동의 이력이 필요한 용도에는 아직 쓸 수 없습니다.
- pyannoteAI로 올라간 오디오는 이 화면에서 지울 수 없습니다. "삭제"는 이 컴퓨터의 사본에만 적용됩니다.
- Silver 검수 화면에는 오디오 재생이 없습니다. 시간 구간은 초 단위 숫자로만 고칠 수 있고, 음성과의 대조는 검수자가 별도로 해야 합니다.
- 검수 도중 화면을 새로 고치면 고치던 내용이 사라집니다. 임시 저장을 두지 않습니다.
- 발화를 추가하거나 지우는 기능은 없습니다. 검증에서 탈락한 발화 31건은 초안에 없으므로 이 화면에서 되살릴 수 없습니다.
